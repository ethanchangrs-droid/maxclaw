# 创建 pre-change-analysis Skill

## 用户要求

基于 [Reasoning/ToolCall展示分析](f73b2192-e42b-4c3d-b4ba-9128c91ecc84) 对话中的分析过程，将其构建为一个全局可用的 skill。要求：
- 当用户有疑问、有需求或发现 bug 时，在做任何代码改动之前先做全面深入的分析
- 提出的方案必须可行，并且考虑合并冲突
- skill 为用户级，全局可用
- 除非用户明确指定了改动位置和方法，否则都要走分析流程
- 分析结果在对话中呈现，不生成单独文件

## 任务计划

1. 阅读参考对话，提炼分析方法论
2. 阅读 create-skill 指南，了解 skill 格式要求
3. 设计 skill 方案，与用户确认
4. 创建 skill 文件

## 执行过程

### 1. 参考对话分析

从对话中提炼出 6 个分析阶段：
- 阶段 1：现状分析 — 深入读代码，绘制数据流，找断点
- 阶段 2：架构差异分析 — 对比不同代码路径，判断能否复用
- 阶段 3：方案设计 — 精确到文件行号的改动方案
- 阶段 4：可行性验证 — 逐个改动点给出代码级证据
- 阶段 5：合并冲突评估 — git 操作类型 + 冲突风险 + 降冲突措施
- 阶段 6：方案优化与确认 — 汇总后等用户确认

### 2. 方案确认

提出方案后用户确认了三个问题：
- skill 名称：`pre-change-analysis`（确认）
- 复杂度门槛：除非用户指定改动位置和方法，否则都要分析（确认）
- 输出方式：对话中呈现（确认）

### 3. 创建 skill

创建路径：`~/.cursor/skills/pre-change-analysis/SKILL.md`
文件行数：194 行（在 500 行限制内）

## 结果

Skill 创建成功，全局可用。包含：
- 6 阶段结构化分析流程
- 操作类型侵入度分类
- 合并冲突风险评估框架
- 用户追问处理矩阵
- 明确的跳过条件和注意事项
